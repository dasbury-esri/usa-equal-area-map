## Context Ownership

Independent headless Chrome instrumentation captured native creation stacks using
WeakRefs, not strong context references. Both the experiment and published app
settled at seven live contexts: two in the parent document and five in the drawer.
Each realm also created one detached 300x150 WebGL2 capability-probe canvas.

The installed SDK source and Vite source mapping identify this call path:
`MapView` validation -> `views/support/WebGLRequirements.js` ->
`views/webgl/capabilities.js`. The latter creates a canvas, calls
`getContext("webgl2", { failIfMajorPerformanceCaveat: true })`, queries GPU limits
and extensions, then caches capability data rather than the context. Both probes
were already collected by settled sampling; forced GC left the seven view
contexts intact. The published app has the same probes, not a different number
of rendering views.

The earlier browser tests held every context in a strong Set. That prevented
probe collection and caused nine contexts to remain live for seven views. Tests
now share `tests/webgl-probe.mjs`, which uses weak references, deduplicates context
objects, and performs CDP garbage collection before a settled count. The app's
existing production tracker already uses WeakRefs and was not changed. Neither
SDK patching nor manually losing capability contexts is warranted. Lifetime
creation totals can still be nine (or eight in globe mode); they are not live
rendering counts.
