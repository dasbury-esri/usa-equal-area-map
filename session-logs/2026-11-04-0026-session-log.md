## Implementation

`experiments/webmap-canvas/tiles.js` recognizes Web Mercator WKIDs 3857,
102100, 102113 and 900913. Tile origin, dimensions, feature extent and LOD
resolution still determine source meters. Analytic inverse spherical Mercator
uses radius 6378137m, longitude `x / R` and latitude `atan(sinh(y / R))`,
converted from radians to degrees. Forward footprint calculation clamps
latitude to approximately +/-85.05112878 degrees.

At each pane's current center latitude, choose the first advertised LOD with
`resolution * cos(latitude) <= scale * 0.0254 / 96`. The established Albers
LOD selection is unchanged. Unwrap footprint longitudes relative to the pane
center, select a compact column interval, then wrap columns modulo the global
tile-grid width and deduplicate. Rows clamp to the valid grid. The existing
256-tile pane budget remains enforced.

Prefer a supplied matching regional Albers source; otherwise use a supplied
Mercator source for any pane. Decode into the existing pane shader path.
Mercator draws plain polygons and polylines only, with existing local colors;
point and label/abbreviation layers are excluded. No style, sprite, glyph or
font assets are fetched. `Marine area` receives the plain water fill.

Independent checks: proj4 agrees within 1e-10 degrees / 1e-7 meters at all
six requested anchors and an eastern-dateline point. The live service advertises
EPSG:3857, 512-pixel tiles and a global Mercator grid. The cosine-latitude
resolution convention is documented by Microsoft's primary tile-system guide:
https://learn.microsoft.com/en-us/bingmaps/articles/bing-maps-tile-system
