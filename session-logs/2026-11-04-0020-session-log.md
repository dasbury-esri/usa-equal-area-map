# Session 0020: Restore Airport Zoom Recentering

Recorded: 2026-11-04 14:43:50-08:00[America/Los_Angeles]

## Request and Scope

David reported that production and subsequent experiments had lost the inset
airport recentering during large zoom moves. Diagnose the regression and restore
it without interfering with more recent work. Changes are local and uncommitted
on `experiment/vt-basemaps`, based on `7902375`; no merge, push or deployment was
requested for this repair. Other workspace repositories are unchanged.

## Cause

`connectZoomAnchor` returned early whenever `framingPreview` was enabled. That
return skipped both the airport projection and scale watcher, and made globe
recenter buttons return the regional home at every scale. History identifies
`f7503c3` (`feat: make responsive framing the default with Albers presets`) as
the change making responsive framing unconditional. The same bypass exists in
the tracked `main` source; this was not introduced by the vector-tile experiment.
The initial regression test failed before the fix with Puerto Rico's airport
272.08 pixels from the pane center at 1:1,000,000.

Simply removing the return would reuse the obsolete fixed 1:24,000,000 home
scale and disturb responsive initialization. ADR-0001 requires distinguishing
responsive fitting from ordinary user navigation.

## Repair

- Restore the existing airport interpolation and manual-pan handling, using
  each view's actual responsive home scale and center.
- Record fitted Alaska and main home centers before applying a responsive fit;
  share the fitted scale with the other insets. Airport coordinates and the
  1:1,000,000 threshold are unchanged.
- Apply the watcher initially so a lazily opened Puerto Rico pane starts at
  its airport when the main map is already deeply zoomed.
- Preserve home scale/center and manual center through genuine context-loss
  recovery. Ordinary view retention remains unchanged.
- Keep the independent overview center, per-pane Maps, vector basemaps,
  layer synchronization, projections and tile data unchanged.

## Measurement Caveats and Separate Issue

Globe-mode `view.toScreen` with a geographic point required a legacy projection
engine not initialized by the application's operator-based projection path.
Loading a raw SDK module did not initialize Vite's optimized MapView copy.
The test therefore obtains the app-loaded projectOperator module, projects the
independently specified airport coordinates, and gives each native view a point
in its own CRS. This is a dev-server fixture, not a built-output test. No extra
projection loader was added to application code.

Tiled mouse-wheel zoom stayed at its assigned scale in separate checks at
1:500,000 and 1:1,000,000. The native view received the wheel event and had wheel
zoom enabled. An in-memory route override disabling only the restored anchor
watcher reproduced the unchanged scale, so this is not attributed to the repair.
The underlying tiled-wheel cause is unresolved and out of this change's scope.
Tile cases still verify programmatic scale changes, native manual drag, airport
centering and recovery, but do not claim working mouse-wheel zoom.

The successful run's console summary originally printed "wheel zoom" for every
case; a reporting-only follow-up now explicitly marks the tiled exclusion.
Lint and syntax checks passed after that change; unchanged browser behavior was
not rerun. The retained raw results predate the added `wheel` reporting field.
