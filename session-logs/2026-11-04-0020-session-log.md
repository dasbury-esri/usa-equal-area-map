## Step 1: Concurrent Service-Sized Pages

Use each loaded service's positive integer `maxRecordCount`, with no fixed
500-record cap or guessed fallback. Each pagination request owns a query clone.
The first geometry page overlaps the count query; after the count establishes
remaining offsets, all remaining pages start without waiting for the first.
Non-pagination services request IDs and counts together, then download ID pages
concurrently. Results are decoded and validated in offset order regardless of
completion order. Layers remain concurrent.

Budget tradeoff: a bounded first page may download before a feature-count
rejection. No further pages are scheduled for an over-budget layer, and no
rejected geometry is admitted. Concurrent pages can consume temporary memory
before cumulative vertex validation; existing feature/vertex admission limits
remain enforced. Count-dependent page offsets cannot be known before count/IDs.

A gated 2501-feature contract advertises maxRecordCount=1000, requires count and
first page overlap and all three pages to start before any resolves, then resolves
pages in reverse order and verifies exact ID order. Nineteen ordinary contracts
pass (frozen-area audit skipped), focused lint and production build pass.

## Step 4: Projected Vector-Tile Experiment

Recorded 2026-11-04 22:56:06+00:00[UTC]
(2026-11-04 14:56:06-08:00[America/Los_Angeles]). This step is a separate
experimental commit, not production acceptance. No push is authorized.

`tiles=<HTTPS VectorTileServer URL>[,<URL>]` accepts the two supplied services.
Sources are selected by advertised CRS, independent of URL order: EPSG:5070
for conus/hi/pr/gu, EPSG:3338 (also advertised as 102006) for ak. A missing
required source is an explicit error, never a fallback to the other source.
For a single-source URL, select only compatible panes. Defaults retain the
original four panes; `panes=conus,ak,hi,pr,gu` enables a five-pane layout.
Minimum scale is now 1:500000. Tile-only and tile-plus-feature inputs work
through the existing dataset/shader path; native acceptance below is tile-only.

Anonymous service metadata supplies tile origin, rows/columns, resolution,
extent and LODs. Decode PBF with `@mapbox/vector-tile` and `pbf`, transform each
feature's own integer extent into source meters, then inverse-project with
proj4 into longitude/latitude before the existing WGS84 pane shader. The pinned
NAD83 definitions match the advertised EPSG codes and the independently fetched
definitions at https://epsg.io/5070.wkt and https://epsg.io/3338.wkt. Published
WKT anchor checks give EPSG:5070 San Juan x=3224258.167837162m and EPSG:3338
Anchorage x=219490.51067978586m. No pane WKT substitutes for a source CRS.
This does not certify datum realization accuracy or use outside a CRS's
authority area of use.

Use `polygon-clipping` and `lineclip` in tile coordinates before inverse
projection. Polygon holes survive; polygon fills have no clip-edge outlines.
Coastline measurement excludes artificial tile-square edges. Lines and points
use half-open right/bottom edge ownership. A synthetic protobuf fixture checks
buffer clipping, a preserved hole with exact 0.84 square-degree area, removed
artificial edges and single line/point ownership. Adjacent tile-grid boundaries
have identical source coordinates. These checks are not exhaustive seam
certification for every projection or source geometry.

Only plain fills, lines and points are drawn. Background/land, water and line
colors are fixed locally, based on geometry and source-layer names. Label/abbr
layers are excluded; no style, sprite, font or glyph assets are requested.
Per-pane datasets prevent a source drawing into other panes. Concurrent tile
requests and decoded promises are shared; the cache has 512 entries, each pane
selection is limited to 256 tiles, and individual decoded response bodies are
limited to 16MB. These are admission limits, not a hard total-memory ceiling.
404/204 tiles are counted as missing; all eight comparison footprints had zero.
Failed metadata/tile requests are retryable. Tile selection is refreshed when
keys change; accepted coverage advances only after a successful, version-current
renderer upload. Existing stale-request protection retains prior geometry.
