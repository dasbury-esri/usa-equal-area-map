## Proposal Only: Move the Drawer Into the Main Document

Recommended as a separate owner-approved follow-up, not implemented here.

1. Move the existing drawer pane markup into a scoped container in the main
   document, retaining pane geometry, controls, accessible labels, projection
   presets, locator sizes and overview extent/leader overlays.
2. Reuse the current lifecycle groups, with direct view references replacing
   iframe load/readiness and postMessage coordination. Keep lazy open/close
   behavior and hidden-tab navigation restoration.
3. Use one SDK realm and one retained regional map/layer registry for all six
   regional views. Retain the separately owned standard-overview composition;
   the SDK's one-parent rule still applies.
4. Scope drawer CSS that currently depends on document/body sizing, and adapt
   leader coordinates and focus handling to the new container. Do not mix this
   structural move with projection, framing, data or dependency changes.
5. Require the same eight-case native matrix and two-tab stress, plus measured
   cold/warm request counts, transferred bytes and startup timings before
   claiming loading improvements. Verify scale sync, recentering, restore,
   panel placement and overview geometry against current screenshots.

Expected benefit: avoid the second document's SDK initialization, worker-pool
initialization and duplicate regional layer objects. Browser caching already
shares some transferred assets; eliminating the iframe does not imply zero
duplicate downloads or feature queries. Each view still needs its own spatial
data and rendering context. Benefits remain a proposal, not measured results.
