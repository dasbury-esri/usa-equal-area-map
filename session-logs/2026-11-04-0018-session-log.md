`originPosition: upperLeft`, and the current degree tolerance. The grid extent

multipart geometry remains the intersects selection filter. `maxAllowableOffset`
is unset. Installed SDK `executeQueryJSON` constructs a FeatureSet without

## Step 3: CPU Projected Bounds

`projectChunkBounds` now accepts the Float32 mesh values and uses each pane's
proj4 converter on actual vertices, not geographic bounding-box corners. A
per-chunk numeric-coordinate cache avoids repeated projections without retaining
another geometry-sized cache. Longitude is normalized before projection.
Bounds receive at least 32m numerical padding; chunks near longitude branch
seams, LAEA antipodes, or nonfinite output fail open. This modestly increases
submitted instances (685590 to 701570 at the initial Lambert framing).

Startup no longer creates a transform-feedback program/buffer or calls
`getBufferSubData` for bounds. The separate `measureGPU` accuracy-test utility
still uses GPU readback; it is not called by startup.

Sixteen Node contracts pass. Native culling-on/off canvas bytes match exactly
at 1920x1080, 2560x1600 and 390x844 in both Lambert and Albers. Both projection
refinement checks retain three layers and one context. These comparisons do
not establish overall polygon fidelity. Evidence:
`/tmp/usa-map-startup-step3-contracts.log`,

`/tmp/usa-map-startup-step3.log`. Source/scratch memory is unchanged from Step 2.
